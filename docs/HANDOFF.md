## 暗順応・恐怖でピントが奪われる・稲光の影（11月26日、Claude Code）

- 作者が選んだ画面効果とシェーダーの3つ（1 暗順応、4 恐怖でピントが奪われる、8 稲光で走る木の影）を作った。
- 暗順応とまぶしさ：`autoExposureCS.hlsl` が自動露出のバッファの [2]（暗さに慣れた度合い）と [3]（まぶしさ）を書き、`exposurePS.hlsl` が共通の `eyeAdaptation.hlsli`（新しい部品）で、照らされていない暗い所の色を青白い白黒へ移し、まぶしい間は露出を上げる。しきい値は `DARK_ADAPTATION_*`・`DAZZLE_*`。
- 恐怖でピントが奪われる：`PostProcess::SetFearFocus` を、`ShowFearVision`（1面・2面）と森の恐怖から、視界の狭まりと同じ強さで渡す。`crtOverlayPS` が深度（t2）から奥行きを戻し、画面の中央の奥行きから外れた所をぼかして重ねる（`crtOverlayParts.hlsli` の `GetDepthOfFieldLayer`）。b0 に `depthOfField` を足した。
- 稲光の影：`Game::RequestEventShadowLight` を足し、森の稲光が光っている間だけ、裸電球の影の仕組み（`PointShadowMap`）を稲光の位置で使う。画質2から付ける。
- 直した不具合：`PointShadowMap::BeginFace` が合成の設定を外していなかったため、距離のキューブマップに何も書けず、影が出ていなかった。撮影で、影のあり・なしの画像が1画素も違わないことから見つけ、上書きにした。**2面の揺れる裸電球の影（画質3）の見え方も変わる**が、画質3の2面はまだ撮影で確かめていない。
- 撮影での確認：一時的に（TEMPVERIFY、消した）、ピントの効果を最大にした1面、暗順応を最大にした1面、稲光を出し続けた森を撮った。影のあり・なしの差の画像で、研究所の外壁に枝と庇の影が落ちていることを確かめた。地面に落ちる木の影は、稲光の光が地面まであまり届かないため、ほとんど見えない。暗順応の慣れる速さ、まぶしさ、ピントの強さの変わり方は、実際に遊んで確かめていない。
- Release・Debug（x64）は警告0。全部のシェーダーを fxc でコンパイルし、失敗0（警告は前からある所だけ）。

## 森の雨で輪郭が浮かぶ人影（11月26日、Claude Code）

- 作者が選んだギミック「雨で輪郭が浮かぶ見えない人影」を、森の小道の始まり（z = -375 を越えた所、約110先）に一度だけ置いた。`ForestRainFigure`（新しいクラス）が状態を進め、`ForestRain::SetFigure` で雨へ渡す。

## 1面の呼吸する壁の暗いギザギザ（11月21日、Claude Code）

- 症状：膨らんだ所だけが格子に沿ったギザギザの形で暗くなり、懐中電灯の光の輪も、平らに止まった所だけが明るく切り取られて見えた。

- 確かめたこと：Release・Debug（x64）とも警告0。自動撮影の `05r`・`05s` で、ギザギザの暗がりが消え、光の輪がなめらかに暗くなること。シェーダーは `breathingWallVS`・`breathingWallPS` 以外、前のコミットとバイトコードが同じ。

## 点光源が壁を抜けて照らす不具合（11月16日）

## DDGI（壁や床で跳ね返った間接光）（11月16日）

- 審査会の指摘「グローバルイルミネーション、エヌビディア DDGI」「レイトレーシング」への対応。NVIDIA の RTXGI は DirectX 12 と DXR が前提で入れられないので、論文（Majercik ほか 2019）の方式を DirectX 11 の Compute Shader で作った（`DDGIVolume`）。
- プローブ：部屋の形（`Renderer::GetRoomOcclusion`。壁の長方形と床・天井の高さ）の範囲に、横は約1.5m 間隔（1方向に32個まで）、高さ4段で並べる。部屋の形を送り直したとき（`GetRoomOcclusionVersion` が変わったとき）に作り直す。森（部屋の形がない）では使わない。
- 1フレームの流れ：`ddgiTraceCS`（1プローブ64本の光線を部屋の形に当て、当たった面の点光源・懐中電灯の直接光（壁との影の判定つき）と、前のフレームの間接光 × 0.8 を求める）→ `ddgiIrradianceUpdateCS`・`ddgiDistanceUpdateCS`（8x8 の放射照度と 16x16 の距離の八面体マップを、ヒステリシス 0.92 で更新。縁の画素もグループ共有メモリから同じシェーダーで書く）→ `ddgiApplyCS`（縦横半分の解像度で、画面の各画素にまわり8つのプローブを、位置・向き・チェビシェフの不等式で重み付けして読む）→ 壁と床のシェーダーが `GetScreenIndirectLight`（t18）を照明に足す。
- DirectX 11 では 16bit の画像を UAV から読めないので、八面体マップは2枚ずつ用意して交互に読み書きしている。光線の向きは毎フレーム乱数で回す（自動撮影と計測では決まった種 1301）。
- 1面→2面の自動撮影で、DDGI なしより平均の明るさ +8.9%（中くらいの明るさが持ち上がる。懐中電灯を消した中央ホールは差が小さい）。間接光の強さは `SCREEN_INDIRECT_LIGHT_INTENSITY`（screenAmbientOcclusion.hlsli、今は1）で変えられる。
- 光漏れの対策（作者が遊んで「光が後ろの壁に漏れる」と見つけた）：画面に当てるとき、点と8つのプローブの間に壁があるプローブを使わないようにした（`IsWallBetween`。部屋の形との交差で直接調べる）。全部の壁を8回調べると DDGI が約2ms になったので、先にプローブの範囲に重なる壁だけをビットの印に集めて調べる。光線の当たった面の跳ね返りでは調べない（数が多く、弱い光で目立たない）。HLSL の `&&` は右側も計算するので、印が0のときに判定を呼ばないよう if を分けた（呼ぶと、範囲外の番号で配列を読むとしてシェーダーのコンパイルが失敗した）。点光源そのものも壁を抜けて照らす（前からある。影がないため）ので、作者が見た漏れがそちらなら別に直す。
- 計測モード：DDGI の時間は1面で約1.2ms、2面で約0.3ms（壁の判定を入れる前は約1.0ms・0.24ms。計測の「本描画」の区間は深度プリパス・SSAO・DDGI を含むので、その分も本描画が増えて見える）。一番重い西棟で1フレーム 9.4ms。Release・Debug（x64）とも警告0。
- 見比べ方：Debug 版の F1 の「DDGI indirect light (probes)」、自動撮影と計測は `--ddgi off`。
- まだのこと：遊んで、暗さが足りなくなっていないか（ホラーの暗さ）と、壁の向こうから光が漏れていないかを確かめる。小物の箱や扉には光線を当てていない（壁・床・天井だけ）。プローブが壁の中に入ったときに位置をずらす処理（論文の probe relocation）は入れていない。

## 天井の照明の接触影（11月16日）

- 審査会の指摘「影が当たっていない部分がおかしく見える」への対応。天井の照明（点光源）には、揺れる裸電球1つを除いてシャドウマップがなく、棚・机・ロッカーの足元に影がなかった。
- SSAO の Compute Shader（`ambientOcclusionCS.hlsl`）で、画素ごとに一番強く照らしている点光源を選び、その光源の方へ約80cmの光線を深度に沿って8歩たどって、物の裏に入ったら影にする（スクリーンスペース・コンタクトシャドウ）。SSAO の画像を2チャンネル（R = 環境遮蔽、G = 接触影）にし、同じぼかしで粒を消す。壁と床のシェーダーは `GetScreenContactShadow` で1回読み、点光源の光に掛ける。懐中電灯は目のそばから照らすので、この方法では影が作れない（シャドウマップがある）。
- 試したこと：最初は壁と床のシェーダーで点光源ごとに求めたが、本描画が1〜2ms重くなった（大きなシェーダーのレジスタが増えたため）。数で上限を付けるとタイル（16x16画素）の形の四角いむらが出た。卓上ライトの傘のように光源を包む器具を「さえぎる物」と見て、机の上に楕円の影が出た（光源のまわり8を調べないようにした）。光がかすめる机の面には点々の自分の影が出た（浮かせる距離・奥行きに比例した差・かすめる角度で弱める）。最初の方式は `C:\Job_application_work_horror\_保管\contact_shadow_per_light_20261116` に移した。
- 計測モード：SSAO の時間が約0.35ms 増えた（0.37→0.73ms。暗証番号の扉の前は1.14ms）。壁と床のシェーダーで読む分は 0.02〜0.07ms。自動撮影の平均の明るさは −0.1%。Release・Debug（x64）とも警告0。
- 計測の注意：何度も続けて計測すると、本描画の時間が 0.3〜0.7ms ほど上下した（ノートPCの温度）。比べるときは、同じ時間帯に続けて測った物どうしで比べる。

- サンプラーが繰り返しの設定なので、小さい段を画面の端で読むと反対側の光が混ざる。端の画素の中心より外は読まないようにした。

## HDR とトーンマッピング（ACES）（11月16日）

- 審査会の指摘「HDR、ブルーム、トーンマッピング、ACES」への対応。本描画を 8bit のバックバッファではなく、16bit の浮動小数点の描き先（`Renderer::BeginHdrScene`、`R16G16B16A16_FLOAT`）へ描き、画面効果の最後に `shader/toneMapPS.hlsl` で1回だけ ACES の曲線を掛けてバックバッファへ移す。HUD とデバッグ画面は、その後にバックバッファへそのまま描く。
- 以前は壁や床のシェーダー（`ApplyFilmicHorrorGrade`）が ACES を28%だけ混ぜて1で切っていた。今は色調の処理は1を超える明るさを残し、曲線は `toneMapping.hlsli` にまとめた。黒を沈める処理は ACES の曲線の足元に任せ、2面の周回が深い分だけを残した。
- ACES を赤・緑・青に別々に掛けると、懐中電灯の暖かい光と霧の色が灰色に寄り、電球が黄緑になった。曲線の75%を輝度に掛けて色の比率を保つようにした（`ACES_HUE_PRESERVATION`）。
- 電球などの自ら光る色は0〜1の「見せたい明るさ」で決めてあるので、曲線の逆（`InverseToneMapEmission`）で HDR の値に直してから足す（`litTexturePS.hlsl`）。ブルームは HDR の明るさを使い、上限を2にした（`BLOOM_MAX_LUMINANCE`）。環境マップ（`ReflectionProbe`）も HDR の形式にした。
- 曲線に入れる前の明るさ `ACES_EXPOSURE` は 0.85。1面→2面の自動撮影51枚で、平均の明るさが元の +3.6%、中くらいの明るさ（中央値）はほぼ同じになる値（1.0 では +16%、0.71 では −13% だった）。森は +2.5%、3面（試作）は +12%。一番明るい所（電球の芯など、上位1%）は、曲線で丸まって少し暗くなる。
- 見比べ方：Debug 版の F1 の「Tone map: ACES (HDR) / Legacy (before HDR)」、自動撮影と計測は `--tonemap legacy`。Legacy は曲線だけ以前の物で、黒を沈める処理を外した分は戻らない。デバッグ表示の間は曲線を掛けない（色分けがずれないように）。
- 計測モード（Release、垂直同期なし）：1フレームが 0.4〜0.5ms 増えた（画面効果 0.43→0.69ms、本描画 +0.1〜0.2ms）。一番重い西棟でも 7.8ms。
- Release・Debug（x64）とも警告0。作者に、実際に遊んで暗い所の見やすさと電球の光り方を確かめてもらう（まだ）。次は、懐中電灯の配光のむら（マルチレベルのブルームは同じ日に入れた）。

## SSR が一度も当たっていなかった不具合（11月13日）

- 「ポンプが水面に映っていない」という指摘から調べると、**水たまりと2面の鏡の SSR が、どこでも何にも当たっていなかった**。
  原因は、深度からビュー空間の奥行きを戻す式が右手系の式（z = -[3][2] / (深度 + [2][2])）だったこと。このゲームのカメラは左手系（`XMMatrixLookAtLH`・`XMMatrixPerspectiveFovLH`）なので、奥行きがずれていた。
  画面の外を映す仕組み（部屋の形・小物の箱・環境マップ）だけで映っていた。
- `rayReflection.hlsli` の `TraceScreenSpaceReflection` を、射影行列の [2][3]（前方の符号）を使う、どちらの手系でも正しい式に直した（今の深度・二分探索・当たった位置の復元・前のフレームの深度。`ScreenSpaceReflection::FinishFrame` は [2][3] も渡す）。
- SSR が当たった所は、本物の色を主にし（混ぜる割合 0.48→0.85）、「近くの縦の面」として映り込みを強めた（`wetFloorPS.hlsl` の `TraceRayReflection`）。
- 確かめたこと：値を色で塗って SSR が当たることを確認。自動撮影で、西棟の柱・排水バルブと配管・ポンプの配管が水面に逆さまに映るようになった。水面と鏡の人影は変わらない。計測モードのライトONのフレーム時間は、全10地点で直す前と同じ（±0.2ms以内）。
- 試したが戻した物：ポンプを5つの箱に分けて映す（丸い胴が四角く映り、ポンプの下に台があるように見えた）。
- ポンプの映り込みは、懐中電灯が水面を強く照らす場所なので控えめ。遊んで見え方を確かめる。

- 今回の比較撮影では、ヒューズ取得済みの状態で入口側から見て、棚の端で影が止まった後に無線の指示が出ることを確認した。ヒューズ数を上書きする撮影用処理は取り除いた。
- 修正前の撮影では、西棟への切り替え中に位置を補間したため、書類保管室を1フレーム通過し、入室の台詞が西棟で先に出ていた。切り替え前後のキーフレームを同時刻にして、途中の座標を通らないようにした。
- 修正後の確認用撮影では、書類保管室で入室時の台詞（05d）と「ライトを消せ」（05e・05f）が順に出た。録音1と4を自動再生し、それぞれ琥珀色の字幕で3行流れること、録音4の後に応答と通信途絶が出ること、中央ホールの録音機のランプが緑になることを画像で確かめた。確認用の撮影位置、自動再生、ヒューズ数の上書きは取り除いた。

- 一時処理を外した最終版を Release・Debug（x64）でビルドし、どちらも警告0・エラー0。Release の `--capture`（1面→2面）と `--forest --capture` はどちらも最後まで通り、終了コード0。画像と動画はリポジトリ外の一時フォルダに出した。

## 西棟の排水跡（11月11日）

- 水が奥へ引く進行に合わせ、浸水メッシュとコースティクスに使う水面の高さを下げる。手前の柱1本と周辺の床だけ、水が過ぎると湿った帯と残り水が現れる。残り水の輪郭は水たまりとして反射し、その周りの濡れた床は懐中電灯を広く弱く返す。
- 自動撮影では水の端を3段階に固定し、同じ位置から排水前・途中・後の床と柱を撮影した。比較用の処理は取り除いた。
- Release・Debug（x64）のビルドはどちらも警告0・エラー0。Release の1面から2面と森の自動撮影は、どちらも終了コード0。
- 実際にバルブを回し、立つ位置や懐中電灯の角度を変えて、排水の前後を見分けられるか確かめる。

## 3面の開発用プレビュー

- タイトルと2面の進行とは独立し、起動引数 `--stage3` から確認できる。階段踊り場から配線をたどり、中継ラック、回線盤、試験停止、主電源、手動解錠、非常口の順に進む。南側の記録室には3回線の手順があり、奥の点検通路は回線室へ続く。北側の観測区画も選べる。中継室の奥で起動し、消灯して歩き、緑の端末へ着くと通信室の裏口を開けられる。見つかったら起動盤側へ戻ると再挑戦できる。林では北と南の中継箱を調べ、独立電源の送信小屋で調査員の原本を回収または消去する。道路の門を越えると選択に応じて結末が変わる。
- 3面の確認中は、Release・Debugともに B キーまたはコントローラーの Back で電池を50ポイント回復できる。
- 確認撮影は南ルートからの原本回収が `--stage3 --capture <保存先>`、北ルートからの原本消去が `--stage3 --capture-features <保存先>`。作者の操作では、足元の配線の見つけやすさ、通信卓の映像に気づくか、足音が途切れるタイミングと雨音への切り替わりを確認する。
